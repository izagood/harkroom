### 2.1 계정 삭제를 어떻게 넣나 (B4)

앱은 가입을 안 받고 워크스페이스 관리자가 초대한다. 계정의 주인은 **각 워크스페이스 서버**다.
그래서 "Harkroom 계정"이라는 하나가 없고, 커뮤니티마다 따로 있다.

- 「나 › 커뮤니티」 각 줄에 **[이 커뮤니티에서 계정 삭제]**. 서버 `DELETE /accounts/me`:
  사람 계정을 `disabled_at` + 세션·PAT·푸시 기기 폐기 + 프로필(이름·아바타) 익명화. 메시지 본문은
  워크스페이스 기록이므로 **관리자 정책**(남김/지움)을 따른다 — 처리방침에 적는다.
- 관리자 마지막 1인은 거절(워크스페이스가 주인 없이 남는다).
- 설계 세부는 security 의견을 받아 확정한다.

### 2.2 App Privacy 라벨 초안

추적 없음. 모은 것은 전부 **앱 기능 · 사용자와 연결됨**:
연락처 정보(이름·로그인 id) · 사용자 콘텐츠(메시지·사진·파일) · 식별자(사용자 id, 기기 푸시 토큰) ·
진단 없음(분석·크래시 SDK 없음). 데이터는 **사용자가 넣은 워크스페이스 서버**로만 간다 —
운영자가 우리(hosted, gate)인 경우와 자가 호스팅을 처리방침에서 나눈다.

## 4. 심사용 데모 (security 검토)

- **전용 테넌트** 하나(gate 로 생성, 예: `review` 커뮤니티). 프로덕션 테넌트와 DB·자격 분리.
- 계정 1개(사람, 일반 멤버 — 관리자 아님). 비밀번호는 ASC 심사 메모에만. 심사 끝나면 돌린다.
- 채널 2~3개 + 미리 쓴 대화 + **데모 에이전트 1개**(심사관이 `@demo` 를 부르면 실제로 답해야 한다).
  에이전트는 우리 쪽 상시 오퍼레이터에서 돌고, 도구 없는 읽기 전용·호출 한도·비용 상한을 건다.
- 데모 에이전트가 심사관에게 아무 말이나 하지 않도록 지시문을 좁히고, 신고(B1)가 이 테넌트에서도 동작해야 한다.
- 심사 메모(영문): 서버 주소·계정·"에이전트는 다른 컴퓨터에서 도는 AI 이고, 앱은 호출만 한다"·Time Sensitive 사용 사유.
